# CLI Audit — 2026-07-17

## Purpose

This audit documents the structural breakage discovered in the NanoBox CLI entry point and runtime, and prescribes the fixes needed to restore end-to-end functionality. It also records the architectural contract going forward.

---

## Critical Finding: Import-Path Breakage

### Symptom

Running any `nanobox` command (other than `--version` or `--help`) fails because `cli/nanobox.bx` and `cli/CommandRuntime.bx` instantiate classes using `cli.X` import paths that **do not exist**. The actual managers live in `models.X`.

### Root Cause

During a refactoring pass, domain-layer classes were moved from `cli/util/`, `cli/system/`, etc. into `models/{system,util,agents,gateway,scheduling,security,sessions,skills,tools,vault,middleware,providers}/`. However, the CLI entry point (`cli/nanobox.bx`) and the runtime dispatcher (`cli/CommandRuntime.bx`) were never updated to match the new locations.

### Impact

**Every CLI namespace is broken.** Even though all 19 command classes exist in `cli/commands/`, the runtime cannot instantiate the managers they depend on. This includes:
- Core lifecycle (`start`, `stop`, `status`, `restart`, `doctor`)
- AI (`chat`, `model`)
- Config & persistence (`config`, `session`, `tokens`)
- Content & security (`agent`, `tool`, `skill`, `vault`, `security`)
- Automation & processes (`cron`, `web`, `worker`, `mcp`, `script`)
- Operations & gateways (`backup`, `update`, `gateway`)

The only commands that work are `--version` and `--help`, which exit before hitting the broken code path.

## Files Affected

### 1. `cli/nanobox.bx` (entry point)

**Broken lines:**
```boxlang
var config = new "cli.util.ConfigManager"()        // ❌ doesn't exist
var result = new "cli.CommandRuntime"( new "cli.PrettyCli"( true ), config ).execute( parsed )  // ❌ PrettyCli doesn't exist at cli.PrettyCli
```

**Fix:**
```boxlang
import models.system.ConfigManager;
import models.util.PrettyCli;

var config = new "models.system.ConfigManager"()
var result = new "cli.CommandRuntime"( new "models.util.PrettyCli"( true ), config ).execute( parsed )
```

**Fix:** Replace every `new "cli.X"` with `new "models.<package>.X"` per the mapping table below. Add `import` declarations at the top of the file for predictability.

### 3. `cli/CommandDispatcher.bx` (handler map)

**Issue:** The `handlers` struct is incomplete — it only lists 11 handlers but `CommandRuntime` dispatches 19+ namespaces. Several namespaces (`backup`, `update`, `web`, `worker`, `mcp`, `script`, `vault`, `security`) are missing from the dispatcher's map.

**Fix options:**
- **Option A (recommended):** Make `CommandDispatcher.dispatch()` delegate to `CommandRuntime.execute()` for the full list, keeping the dispatcher as a thin routing layer.
- **Option B:** Add the missing entries to the `handlers` struct so the two stay in sync.

### 4. Launchers (`nanobox`, `nanobox.bat`, `nanobox.ps1`)

**Status:** ✅ No changes needed. All three wrappers correctly resolve BoxLang and `nanobox.bx` through the active symlink with fallback to the local copy. They are pure shell and know nothing about BoxLang packages.

## Architectural Contract (Going Forward)

From v0.1.0 onward, the layer contract is pinned:

- **`cli/`** is the *interface layer*. Only CLI surface classes live here:
  - `nanobox.bx` (entry), `CommandDispatcher.bx`, `CommandRuntime.bx`, `CoreLifecycleCommand.bx`, `InteractiveChat.bx`, `InteractiveChatRenderer.bx`, `ModelCommand`, `ProviderCommand`
  - `cli/commands/*Command.bx` — one per CLI namespace
- **`models/`** is the *domain layer*, partitioned by bounded context:
  - `models/system/` — `ConfigManager`, `ProcessManager`, `BackupManager`, `ScriptManager`, `UpdateManager`
  - `models/util/` — `PrettyCli`, `TokenTracker`
  - `models/{agents,gateway,middleware,providers,scheduling,security,sessions,skills,tools,vault}/`
- **`worker/`** — long-running supervisor (Scheduler, WorkerSupervisor, WorkerCommand). Will be populated in Task 5.
- **No code in `web/`, `~/` directories, or at the project root beyond launchers and config.**

**Rule:** Instantiate domain classes as `models.<package>.<Class>`, never `cli.<Class>`.
- ✅ `new "models.system.ConfigManager"()`
- ✅ `new "models.sessions.SessionManager"()`
- ❌ `new "cli.SessionManager"()`
- ❌ `new "cli.util.ConfigManager"()`
